# Stage A chain (D1-8)
- Run: `sbatch run_d1_8_chain_gaudi.sh` (one gaudi allocation: 4 cards, 7 days). `./run_d1_8_chain_gaudi.sh --dry-run` prints the plan and runs nothing (no cd, no card checks).
- Loop: before every phase the driver re-reads `chain/phases.txt` (blank lines and `#` comments ignored), exits 0 if `chain/STOP` exists, skips phases that have a `chain/done/<phase>` marker, and runs the first remaining one as `bash chain/<phase>.sh` from the repo root. It exits 0 when a pass finds nothing left; a failed phase or a missing script ends it with exit 1, it never continues past a failure.
- `phases.txt` holds one phase name per line (`armD pilot_a probe_a pilot_b probe_b gate main constlr`, later `f_*`); the pilots stop after epoch 4, the end of the 4-epoch LR warmup, and the probes read their `export/teacher_backbone_epoch_0004.pth`. `<phase>.sh` is that phase's script; it only has to exist by the time the driver reaches the phase.
- The driver writes `done/<phase>` (empty marker, on exit 0), `log/<phase>.out` (stdout+stderr, appended on re-runs) and `times.csv` (`phase,start_iso,end_iso,seconds,exit_code`, UTC). One timestamped line per phase transition goes to the Slurm `.out`.
- `STOP` is written by the gate when neither pilot beats arm D and holds the table. `gate.py` then exits 2, so the `gate` phase counts as failed and the job ends FAILED (no `done/gate`); to continue, `rm chain/STOP` before re-submitting, or re-run `gate.py` by hand on fixed inputs (a decision removes a stale `STOP`; a STOP removes stale `main_*.txt`).
- `python chain/gate.py --arm_d R --probe_a R --probe_b R --pilot_a S --pilot_b S --out chain` writes `main_lr.txt` (the chosen pilot's effective peak LR, an absolute value: `effective_peak_lr` from its `args.json`, else the highest `lr` in `ssl_losses.csv` with a WARNING in the report), `main_lr_scaling.txt` (always `absolute`, a record only: `main.sh` always passes `--no_lr_scaling`), `main_epochs.txt` (`40`, or `30` when an epoch takes over 90 min: the pre-registered threshold is unchanged, and the time is measured on the chosen pilot's full-backbone epochs only, i.e. the step-weighted mean `step_time` of its CSV rows with `epoch >= 1`, so the frozen first epoch and its compile row do not count) and `gate_report.md`; `main.sh` reads `main_lr.txt` and `main_epochs.txt`. Exit codes: 0 decision, 2 STOP, 1 unreadable input or a bad `--min_gain` (0 to 0.1) / `--max_epoch_minutes` (above 0); on 1 nothing in `chain/` is touched.
- `constlr` (now the last line of `phases.txt`; Stage B's `f_*` lines go after it): `chain/constlr.sh` continues Stage A SSL with Meta's DINOv3 recipe into `ssl_dinov3_cxr_constlr_seed_100`: the LR flat after the 4-epoch warmup (`--lr` = `--min_lr` = `chain/main_lr.txt`, `--no_lr_scaling`) and the Gram teacher refreshed every 10,000 steps at most three times (`--gram_refresh_steps 10000,20000,30000`, then fixed: DINOv3 Appendix C and the released config's `gram.max_updates: 3`, as in the main run; passed explicitly because the list is locked on `--resume`). `--epochs 1000` is a ceiling that is never reached: the trainer locks `--epochs`, `--lr`, `--min_lr` and `--gram_refresh_steps` on `--resume` but not `--stop_after_epochs`, which is read from `chain/constlr_stop_after.txt` (a positive integer of at most 1000, the epoch to stop after). Like `main_lr.txt`, that file exists only on the cluster, never in the repo, so an rsync cannot overwrite a raised value; create it before the chain reaches the phase (`echo 30 > chain/constlr_stop_after.txt`). A missing, empty, non-integer or above-1000 file fails the phase with an ERROR before anything is launched. To extend the run: edit that number, `rm chain/done/constlr`, `sbatch run_d1_8_chain_gaudi.sh`; it resumes from its last epoch checkpoint.
- `hires` (after `constlr` in `phases.txt`; "DINO-X ConstLR 512 px" in the ledger): `chain/hires.sh`, DINOv3's constant-schedule recipe at 512 px, a SEPARATE run `ssl_dinov3_cxr_constlr512_seed_100` from the stock DINOv3 weights: `constlr.sh` with only the crops and the batch changed (global 512, local 224, Gram teacher `chain/hires_gram_size.txt`: 1024, or 512 if the probe says so; per-card batch `chain/hires_batch_per_gpu.txt` from the SSL memory probe `run_probe_ssl_gaudi.sh`, without which the phase fails before launching). Its LR is `chain/main_lr.txt` (constlr's absolute 0.002 at global batch 256) converted to the trainer's sqrt_wrt_1024 base and scaled by the trainer to this run's global batch G (`--lr` = `--min_lr`, no `--no_lr_scaling`: constlr's LR exactly at G = 256, lower by sqrt(G/256) below), flat after the 4-epoch warmup; Gram refreshes are constlr's 10k/20k/30k steps x 256/G (the same epoch fractions); `--epochs 1000` ceiling; stop epoch `chain/hires_stop_after.txt` (30 to start; extend as constlr: raise it, `rm chain/done/hires`, re-submit). Later data expansions start new stages from its full checkpoint with `ssl_pretrain.py --init_from_checkpoint`.
- `hires` Gram-512 twin ("DINO-X ConstLR 512 px, Gram teacher 512 px"; not a phase, never in `phases.txt`): `sbatch run_d1_8hires_gram512_gaudi.sh` (its own 4-card, 7-day job) runs `chain/hires.sh` with `HIRES_GRAM=512 HIRES_RUN_SUFFIX=_gram512`: the same recipe with only the Gram teacher size changed, into its own run dir `ssl_dinov3_cxr_constlr512_gram512_seed_100`, so it can run next to the 1024 run, which is still `sbatch run_d1_8_chain_gaudi.sh` with the `hires` phase (run dir `ssl_dinov3_cxr_constlr512_seed_100`). It shares `chain/main_lr.txt`, `chain/hires_stop_after.txt` and `chain/hires_batch_per_gpu.txt` with it and does not read `chain/hires_gram_size.txt`; its log is the Slurm `.out` (no `chain/log` file, no `chain/done` marker). Re-submitting the same script continues from its last epoch checkpoint; to extend it, raise `chain/hires_stop_after.txt` and re-submit.
- No-Gram trunk ("DINO-X ConstLR 224, no Gram"; not a phase, never in `phases.txt`): `sbatch run_d1_8_constlr_nogram_gaudi.sh` (its own 4-card, 7-day job) runs `chain/constlr.sh` with `CONSTLR_NOGRAM=1`: the `constlr` launch line with `--gram_refresh_steps 10000,20000,30000` replaced by `--no_gram` (no Gram teacher built, loaded or run: no Gram loss, no refreshes) and, since 2026-10-26 (Jarod), three settings of DINOv3's training recipe ahead of it, `--drop_path_rate 0.3 --rope_rescale_coords 2 --untie_local_cls_norm` (student, train mode only; so the trunk is no longer an exact ConstLR-224 control, and its branches pass them too), into its own run dir `ssl_dinov3_cxr_constlr_nogram_seed_100`, so it can run next to the chain's `constlr` run (`ssl_dinov3_cxr_constlr_seed_100`), which it is compared with: the same stock init, `chain/main_lr.txt` LR, `--min_lr` = `--lr`, `--no_lr_scaling`, `--epochs 1000` ceiling, global batch 256 (64 per card on 4 cards) and seed. The stop epoch comes from `chain/constlr_nogram_stop_after.txt` (a positive integer of at most 1000, 100 for the 7-day job; cluster-only like `constlr_stop_after.txt`, which this run does not read); a missing, empty or invalid file, or a `CONSTLR_NOGRAM` other than empty or `1`, fails with an ERROR before anything is launched, and with the variable unset or empty `constlr.sh` is the phase exactly as above. Its log is the Slurm `.out` (no `chain/log` file, no `chain/done` marker): the first lines show the `run: ssl_dinov3_cxr_constlr_nogram_seed_100 (no Gram teacher ...` line and the trainer's `Gram: OFF (--no_gram)` line, and no `Gram refresh scheduled` line. Re-submitting the same script continues from its last epoch checkpoint (`--resume` locks `no_gram`, the LR and the ceiling, not the stop epoch); to extend it, raise `chain/constlr_nogram_stop_after.txt` and re-submit. Gram-anchored branches start from its `ckpt/epoch_NNNN.pth` (every 10th epoch is kept) while it keeps running. The plain twin, `sbatch run_d1_8_constlr_nogram_plain_gaudi.sh` (`CONSTLR_NOGRAM=1 CONSTLR_PLAIN=1`; for a group member to submit), is the same line without those three recipe flags, so `--no_gram` is its only difference from `constlr` (the one-variable Gram-off control), into `ssl_dinov3_cxr_constlr_nogram_plain_seed_100`, with the stop epoch from `chain/constlr_nogram_plain_stop_after.txt` (cluster-only too); `CONSTLR_PLAIN` without `CONSTLR_NOGRAM`, or with any `CONSTLR_BRANCH_*` (no branches of it yet), fails with an ERROR before anything is launched. The one-flag-off recipe ablations, `sbatch --job-name=d1-8-nogram-no-drop_path --export=ALL,CONSTLR_ABLATE=drop_path run_d1_8_constlr_nogram_ablate_gaudi.sh` (and likewise `rope` and `local_norm`; `CONSTLR_NOGRAM=1 CONSTLR_ABLATE=<value>`; Jarod, 2026-10-26; for group members to submit, one arm each; the three submit lines are in the launcher's header), are the no-Gram trunk's line with exactly one of its three recipe flags removed (`drop_path`: `--drop_path_rate 0.3`; `rope`: `--rope_rescale_coords 2`; `local_norm`: `--untie_local_cls_norm`), so each flag's effect on the frozen probe and the cosine maps reads on its own between the plain trunk (all three off) and the no-Gram trunk (all three on), into `ssl_dinov3_cxr_constlr_nogram_no_<value>_seed_100` with the stop epoch from `chain/constlr_nogram_no_<value>_stop_after.txt` (cluster-only too; no arm shares a run dir or a stop file with another arm or with a trunk); re-submit with the same `CONSTLR_ABLATE`, which the launcher requires; a `CONSTLR_ABLATE` other than empty or those three values, without `CONSTLR_NOGRAM`, or with `CONSTLR_PLAIN`, `CONSTLR_ARK` or any `CONSTLR_BRANCH_*` (no branches of an arm), fails with an ERROR before anything is launched. The Ark-teacher twin, `sbatch run_d1_8_constlr_arkteacher_gaudi.sh` (`CONSTLR_NOGRAM=1 CONSTLR_ARK=1`; Jarod, 2026-10-26), is the no-Gram trunk's line plus `--cyclic_ark_teacher --heads per_dataset <lock flag> --keep_all_checkpoints` (the Ark+ / FX teacher in the trainer: the datasets in turn, largest first, one per batch, a cycle per epoch; no per-step EMA, the teacher frozen through every pass and blended 0.8 / 0.2 with the student after each dataset's release pass, on clean views; one DINO and one iBOT head per dataset; every epoch checkpoint kept, about 4.3 GB each). Its lock arm is a per-run ablation set at launch by `CONSTLR_ARK_LOCK` (0 when unset or empty): 0 passes `--no_lock_half_pass` (each dataset's release pass alone, 2665 steps a cycle at 256) into `ssl_dinov3_cxr_constlr_arkteacher_seed_100` with the stop epoch (= cycle) from `chain/constlr_arkteacher_stop_after.txt`; 1 (`sbatch --export=ALL,CONSTLR_ARK_LOCK=1 ...`) passes `--lock_half_pass` (Foundation X's lock-release: per dataset a lock pass over a random half with the backbone frozen (LR 0, no optimizer step), then the full release pass; 3997 steps a cycle) into `ssl_dinov3_cxr_constlr_arkteacher_lock_seed_100` with `chain/constlr_arkteacher_lock_stop_after.txt` (both cluster-only), so the arms never share a run dir or a stop file; its Gram branches are `sbatch --export=ALL,CONSTLR_BRANCH_ARK=1[,CONSTLR_ARK_LOCK=1] run_d1_8_branch_gram_gaudi.sh <K> <STOP> [EVERY] [COUNT]` (that trunk's line with `--no_gram` replaced by the branch pair, the lock inherited from its args.json, run dir `${TRUNK%_seed_100}_e<K %04d>_gram_every<EVERY>x<COUNT>_seed_100`; EVERY = its epoch_length refreshes at cycle boundaries); `CONSTLR_ARK` without `CONSTLR_NOGRAM`, with `CONSTLR_PLAIN` or with any `CONSTLR_BRANCH_*`, `CONSTLR_BRANCH_ARK` without the `CONSTLR_BRANCH_*` variables, a `CONSTLR_ARK_LOCK` other than empty, 0 or 1 or one set without `CONSTLR_ARK` / `CONSTLR_BRANCH_ARK`, and a branch trunk whose args.json records the other lock arm, fail with an ERROR before anything is launched. `run_d1_8_arkteacher_smoke_gaudi.sh` (75 minutes, the same `CONSTLR_ARK_LOCK`) runs its line for 2300 steps into `ssl_dinov3_cxr_arkteacher[_lock]_smoke_seed_100`, past the first dataset boundary and teacher blend in either arm.
- Gram-anchored branches ("DINO-X ConstLR 224, Gram-anchored branch"; not phases, never in `phases.txt`): `sbatch run_d1_8_branch_gram_gaudi.sh <K> <STOP> [EVERY] [COUNT]` (its own 4-card, 7-day job; EVERY and COUNT default to 10000 and 3: Meta's 10k x 3, DINOv3 Appendix C) runs `chain/constlr.sh` with `CONSTLR_BRANCH_EPOCH=K CONSTLR_BRANCH_STOP=STOP CONSTLR_BRANCH_EVERY=EVERY CONSTLR_BRANCH_COUNT=COUNT`: the no-Gram trunk's launch line with only `--no_gram` replaced by `--branch_from /workspace/ssl_dinov3_cxr_constlr_nogram_seed_100/ckpt/epoch_<K %04d>.pth --gram_refresh_steps <list>`, i.e. the trunk continued exactly from its epoch-K checkpoint (`ssl_pretrain.py --branch_from`: student, EMA teacher, optimizer, step, epoch, schedule position, data order and RNG restored) with the Gram teacher on, anchored to that checkpoint's EMA teacher backbone, weight 2.0 and teacher 448 (the trainer defaults). It writes a NEW run dir `ssl_dinov3_cxr_constlr_nogram_e<K %04d>_gram_every<EVERY>x<COUNT>_seed_100` (the cadence is in the name, so two cadences from the same K never share a dir; the trunk keeps running untouched) and stops after epoch STOP (no stop file is read). The refresh list is absolute global steps: K x the trunk's real `epoch_length` (read from `ssl_dinov3_cxr_constlr_nogram_seed_100/args.json`, where the trainer writes it; never assumed) + i x EVERY for i = 1..COUNT, so every resubmit passes the same list, which `--resume` locks (`10 40` at the trunk's epoch_length 2666 refreshes after 36660,46660,56660 into `..._e0010_gram_every10000x3_seed_100`; `10 40 2666 30` refreshes once per epoch for 30 epochs into `..._e0010_gram_every2666x30_seed_100`). Refused with an ERROR before anything is launched: a wrong argument count, K or STOP not a positive integer without a leading zero (`printf %04d` would read it as octal), EVERY not a positive integer of at most 9 digits, COUNT of at most 4, STOP above the 1000 ceiling or not after K, a trunk `args.json` that is missing or holds no positive `epoch_length`, a last refresh (K x `epoch_length` + COUNT x EVERY) past the end of the 1000-epoch schedule (1000 x `epoch_length`), where it could never run, `CONSTLR_NOGRAM` set as well, and a missing source checkpoint while the branch dir has no epoch checkpoint of its own yet. To extend a branch: resubmit with a larger STOP and the same K / EVERY / COUNT (they name the run dir and fix the list); it resumes from its last epoch checkpoint, and the source is read only at the branch's start, so the trunk may have pruned it by then. Its log is the Slurm `.out` (no `chain/log` file, no `chain/done` marker): the first lines show the `run:` line, the `gram refresh steps:` line, the trainer's `Gram refresh scheduled after step ...` lines and its `branched from ...` line (a resubmit: `resumed from ...`).
- Append Stage B: write `chain/f_<name>.sh`, then `echo f_<name> >> chain/phases.txt`. It can be done while the job runs, as long as the script exists before the driver reaches that line.
- Re-submit: `sbatch run_d1_8_chain_gaudi.sh` again continues from the first phase without a `done/` marker. A phase that was killed or failed starts over, so phase scripts must be safe to re-run or resume; `rm chain/done/<phase>` redoes a finished one.
- Tests: `python3 chain/test_gate.py` (decision rule, log parsing, and the driver loop with stub phases; needs Python 3.10+ and bash).
